# Contributing

Thanks for helping! Issues and pull requests are welcome. Before a large change, open an issue to
discuss it.

## Setup

You need Windows, Visual Studio 2022 (C++ desktop workload), CMake 3.20+ and Python 3.11+. To try
the mod: BioShock Infinite on Steam and Archipelago 0.6.7+.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\pre-commit install
```

`build.ps1` uses `.venv` when it exists. `pre-commit install` adds two git hooks: the formatters
and checks of `.pre-commit-config.yaml` on every commit, and the commit message format.

```powershell
.\build.ps1           # build the DLL, the loop test and the apworld
.\build.ps1 -Install  # ... then copy the DLL into the game and the apworld into Archipelago
.\build.ps1 -Test     # ... then run the loop test
.\build.ps1 -Format   # format C++ (clang-format) and Python (ruff)
.\build.ps1 -Lint     # every check of the CI (pre-commit run --all-files)
```

If PowerShell refuses to run the script: `powershell -ExecutionPolicy Bypass -File build.ps1`.

## Layout

| Folder | Contents |
| --- | --- |
| `mod/` | The game mod (C++): sources (`src/`), third-party libraries (`extern/`), loop test (`tests/`) |
| `apworld/` | The Archipelago world (`bioshock_infinite/`, its tests in `test/`), packager and test runner |
| `tools/` | Scripts reading the installed game to generate the world's tables and the mod's images |
| `assets/` | Source images |

Each module of the mod starts with a header comment (`mod/src/*.h`): its commands, its threading
and the game behavior it relies on. Read it before changing the module.

## Rules

### Compatibility

- **Never change or reuse an existing item or location id or name.** Seeds already generated and
  players' saves depend on them. `apworld/bioshock_infinite/test/ids.json` records them and the tests
  fail if one changes. Add new ones after the existing ones (see the id ranges in
  `apworld/bioshock_infinite/data.py`), then record them (see Testing).
- Bump `world_version` in `apworld/bioshock_infinite/archipelago.json` for every change that
  affects generation or slot_data. It is also the version of the DLL.
- The mod only supports the Steam build fingerprinted in `mod/src/game_build.h`. Every address
  lives there, with a comment saying what it is and how it was found.

### The mod (C++)

- Game thread only: everything runs from the per-frame tick (`dllmain.cpp`) or the ProcessEvent
  hook. Never keep a game object pointer from one frame to the next; read memory through
  `ue3::ReadBytes` / `ue3::WriteBytes`, which survive bad pointers.
- Install hooks from the game thread, on first use (see `pehook::EnsureInstalled`): hooking from
  `DllMain` or the init thread freezes the game.
- Prefer calling the game's own UnrealScript functions (`engine::Call`) to writing its memory: the
  game then handles UI, sounds and saving.
- Never give anything to the game while a vending screen is open or closing
  (`shop::GrantsBlocked`), nor an item the game can't resolve yet (`inventory`): both crash it.
- No C++ exception may reach the game: the tick and the ProcessEvent filters catch and log them.
- Commands between the client and the mod are plain text lines. When a reply changes, update the
  client and the fake game of `mod/tests/loop_test.cpp` together.
- Debug-only features stay behind `debug=1` (`apclient::DebugEnabled`).

### The apworld (Python)

- Follow Archipelago's [world API](https://github.com/ArchipelagoMW/Archipelago/blob/main/docs/world%20api.md)
  and [style](https://github.com/ArchipelagoMW/Archipelago/blob/main/docs/style.md).
- The tables `checkpoints.py`, `gear.py`, `infusions.py`, `machines.py`, `upgrades.py` and
  `voxophones.py` are generated by `tools/`, like `mod/src/ap_icon.h`, `ap_emblem.h` and
  `ap_screamer.h`: change the tool and regenerate, never edit them by hand. The tools find the
  game in the Steam libraries (or `BIOSHOCK_INFINITE_DIR`).
- The game's files are never committed.

### Style

- English everywhere: code, comments, logs, docs. In-game texts are translated in the game's five
  languages (`ap_menu.cpp`, `ap_notify.cpp`).
- Comments explain why, not what. Keep them next to the code they describe and up to date.
- Formatting is enforced by the pre-commit hooks (clang-format 17, ruff).
- The C++ builds at the highest warning level with warnings as errors (`/W4 /WX`). Fix a warning
  instead of silencing it; when it is intended, suppress it on that line with a comment saying why.
- The spell checker (typos) only reports. Game identifiers keep the game's spelling, even when it
  is wrong (`BW_SkyhookSeige`): add them to `[tool.typos]` in `pyproject.toml`.

## Testing

- **Loop test**: `.\build.ps1 -Test` generates a seed with `mod/tests/players/`, starts an
  Archipelago server and runs the real client against a fake game. It must pass; add checks when
  you change the client's behavior.
- **Apworld tests**: `python apworld/run_tests.py <Archipelago source checkout>` runs
  `apworld/bioshock_infinite/test` with Archipelago's test runner; add `--general` for Archipelago's
  own tests of every world. The checkout needs its requirements and pytest:

  ```powershell
  git clone --branch 0.6.7 https://github.com/ArchipelagoMW/Archipelago
  cd Archipelago
  python ModuleUpdate.py --yes
  python -m pip install -r ci-requirements.txt
  ```

  After adding items or locations, record their ids once: set `BSAP_UPDATE_IDS=1` and run the tests.
- **In game**: anything touching the game itself needs a real playthrough of the affected part.
  Say in the pull request what you tested in game.

### Debug mode

`debug=1` in `BioShockAP.ini` (next to the DLL, created after the first connection) adds:

- an overlay with the connection state and frames around the checks left nearby (F6 to toggle,
  F7 next target, F8 teleport to it);
- test helpers: F4 infinite health, F5 one-hit enemies, Ctrl+1..6 traps, Ctrl+0 to stop them;
- a text command bridge on `127.0.0.1:38300`, with every command of the modules and inspection
  tools (`props`, `get`, `trace`...): see the header comments in `mod/src`.

The mod logs to `BioShockAP.log`, next to the DLL.

## Commits and pull requests

- Small, focused commits following [Conventional Commits](https://www.conventionalcommits.org):
  `feat:`, `fix:`, `refactor:`, `docs:`, `build:`, `test:`, `ci:`... The commit-msg hook checks it.
- The CI (lint, apworld tests, build, loop test) must be green.

## Releases

Bump `world_version`, merge, then push a matching tag (`git tag v0.1.0 && git push origin v0.1.0`).
The release workflow runs the CI, then publishes the DLL, the apworld, the template YAML and a zip.
Versions 0.x are marked as pre-releases.
